# iotdb-gorm 使用说明

## 1. 组件定位

`iotdb-gorm` 是 Apache 官方 `iotdb-client-go` 上的 GORM 适配层。应用按 GORM 的 `Table`、`AutoMigrate`、`Create`、`CreateInBatches`、`Where`、`Find` 等方式调用；批量写入会转换为官方 Tablet API，不会逐行拼接 INSERT SQL。

当前实际验证范围：

| IoTDB 服务端 | 模型 | 状态 |
|---|---|---|
| 1.3.1 | TreeModel | 已真机验证 |
| 2.0.8 | TableModel | 已真机验证 |
| 2.0.10 | TableModel | 待独立真机验证 |

组件固定使用 Go `1.23.2`、GORM `v1.23.4`。TreeModel 查询使用官方 `iotdb-client-go v1.3.7`；Tablet 写入和 TableModel 使用官方 `iotdb-client-go/v2 v2.0.8`。

不需要在业务服务器或应用镜像中额外安装 IoTDB client：官方 Go 客户端会作为 Go module 依赖编译进应用。应用只需能够通过 RPC 端口（通常是 `6667`）连接 IoTDB 服务端。

## 2. 安装与生命周期

使用发布 tag 引入依赖，不建议长期依赖 `main`：

```bash
go get github.com/HY-805/iotdb-gorm@<发布标签>
```

每个 `gorm.Open` 会创建并持有官方客户端连接池。服务退出时必须关闭：

```go
defer func() {
	if err := gormiotdb.Close(db); err != nil {
		// 记录关闭错误
	}
}()
```

IoTDB 不提供与 GORM 默认事务回调等价的关系型事务语义，因此初始化时必须设置 `SkipDefaultTransaction: true`。

## 3. TreeModel：IoTDB 1.3.1

TreeModel 是默认模型。`Config.Database` 必须是受控根路径，例如 `root.datacenter_compatible`；`db.Table("device001")` 会映射为设备路径 `root.datacenter_compatible.device001`。

### 3.1 连接、建模与单设备写入

```go
package main

import (
	"context"
	"log"
	"os"
	"time"

	gormiotdb "github.com/HY-805/iotdb-gorm"
	"gorm.io/gorm"
)

type DeviceTelemetry struct {
	Time        time.Time `gorm:"column:time" iotdb:"time"`
	Temperature float64   `gorm:"column:temperature"`
	Online      bool      `gorm:"column:online"`
}

func main() {
	db, err := gorm.Open(gormiotdb.New(gormiotdb.Config{
		// ModelMode 省略时默认为 TreeModel。
		NodeURLs: []string{"127.0.0.1:6667"},
		Username: "root",
		Password: os.Getenv("IOTDB_PASSWORD"),
		Database: "root.datacenter_compatible",
	}), &gorm.Config{SkipDefaultTransaction: true})
	if err != nil {
		log.Fatal(err)
	}
	defer gormiotdb.Close(db)

	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()
	if err := gormiotdb.Ping(ctx, db); err != nil {
		log.Fatal(err)
	}

	device := db.WithContext(ctx).Table("device001")
	if err := device.AutoMigrate(&DeviceTelemetry{}); err != nil {
		log.Fatal(err)
	}
	if err := device.Create(&DeviceTelemetry{
		Time:        time.Now(),
		Temperature: 23.5,
		Online:      true,
	}).Error; err != nil {
		log.Fatal(err)
	}
}
```

`AutoMigrate` 只会创建缺失 measurement 或兼容的新增 measurement，并校验已有类型/对齐方式；不会执行删除、改名或类型变更。

### 3.2 多设备批量写入

使用 `iotdb:"device"` 指定每一行的设备路径。该字段只用于路由，不会写为 measurement。适配层会按设备分组、按时间排序，然后使用 `InsertAlignedTablets` 或 `InsertTablets` 写入。

```go
type BatchTelemetry struct {
	Time       time.Time `gorm:"column:time" iotdb:"time"`
	DevicePath string    `gorm:"column:device_path" iotdb:"device"`
	Value      float64   `gorm:"column:value"`
}

rows := []BatchTelemetry{
	{Time: time.Now(), DevicePath: "device_cn_01", Value: 20.5},
	{Time: time.Now(), DevicePath: "device_cn_02", Value: 21.3},
}
if err := db.Table("logical_batch").CreateInBatches(&rows, 1000).Error; err != nil {
	return err
}
```

固定路径表名和 `DevicePath` 都不能携带 SQL 表达式；完整设备路径必须位于 `Config.Database` 下。同一设备内的时间戳必须唯一，重复时间戳会返回错误。默认使用对齐写入；需要非对齐写入时设置 `Aligned: gormiotdb.Bool(false)`。

### 3.3 查询

TreeModel 的时间戳是服务端隐式结果列，不要在 `Select(...)` 中显式包含 `time`。可正常在 `Where`、`Order` 中使用时间条件：

```go
var rows []DeviceTelemetry
err := db.WithContext(ctx).
	Table("device001").
	Where("time >= ? AND time < ?", begin, end).
	Order("time ASC").
	Limit(1000).
	Find(&rows).Error
```

`count(*)` 是各 measurement 的聚合结果，不等价于关系表的行数，不能直接依赖 GORM `Count` 表示设备记录数。IoTDB 1.3.1 对全 NULL TEXT 的返回无法可靠区分空字符串和 NULL，适配层会按 `nil` 处理。

## 4. TableModel：IoTDB 2.0.8

TableModel 必须显式设置 `ModelMode: gormiotdb.TableModel`。`Database` 是关系表数据库名，必须满足普通标识符规则，例如 `iotdb_compatible`。TAG、ATTRIBUTE、FIELD 均要显式标记。

下面片段沿用上例的 `os`、`gormiotdb`、`gorm` 和错误处理上下文：

```go
type TableTelemetry struct {
	Time        time.Time `gorm:"column:time" iotdb:"time"`
	Region      string    `gorm:"column:region" iotdb:"tag"`
	DeviceID    string    `gorm:"column:device_id" iotdb:"tag"`
	Description string    `gorm:"column:description" iotdb:"attribute"`
	Temperature float64   `gorm:"column:temperature" iotdb:"field"`
	Note        *string   `gorm:"column:note" iotdb:"field"`
}

db, err := gorm.Open(gormiotdb.New(gormiotdb.Config{
	ModelMode: gormiotdb.TableModel,
	NodeURLs:  []string{"127.0.0.1:6667"},
	Username:  "root",
	Password:  os.Getenv("IOTDB_PASSWORD"),
	Database:  "iotdb_compatible",
}), &gorm.Config{SkipDefaultTransaction: true})
if err != nil {
	return err
}
defer gormiotdb.Close(db)

telemetry := db.Table("telemetry")
if err := telemetry.AutoMigrate(&TableTelemetry{}); err != nil {
	return err
}
```

首次 `AutoMigrate` 会使用幂等 DDL 创建缺失数据库、表和兼容的新增列，运行账号需具备相应 DDL 权限。写入和查询示例：

```go
note := "normal"
rows := []TableTelemetry{
	{Time: time.Now(), Region: "cn", DeviceID: "d1", Description: "sensor", Temperature: 20.1},
	{Time: time.Now().Add(time.Millisecond), Region: "cn", DeviceID: "d1", Description: "sensor", Temperature: 20.2, Note: &note},
}
if err := telemetry.CreateInBatches(&rows, 1000).Error; err != nil {
	return err
}

var found []TableTelemetry
err = telemetry.
	Where("region = ? AND device_id = ? AND time >= ?", "cn", "d1", begin).
	Order("time ASC").
	Find(&found).Error
```

TableModel 批量写入使用官方 `NewRelationalTablet` 和 `TableSessionPool.Insert`。一个 `CreateInBatches` 会按表、行数和字节上限拆分为多个 Tablet；不会退化为逐行 RPC。

## 5. DSN 与结构化配置

推荐生产环境使用结构化 `Config`，避免将密码放入日志、命令行或配置快照。DSN 适合本地快速验证：

```go
db, err := gorm.Open(gormiotdb.Open(
	"iotdb://root:password@127.0.0.1:6667/root.datacenter_compatible?model=tree&aligned=true&batch_size=1000",
), &gorm.Config{SkipDefaultTransaction: true})
```

常用 DSN 参数：

| 参数 | 示例 | 说明 |
|---|---|---|
| `model` | `tree`、`table` | 模型类型；默认 `tree` |
| `aligned` | `true`、`false` | TreeModel 是否对齐写入 |
| `pool_size` | `8` | 官方连接池最大 Session 数 |
| `connect_timeout` | `10s` | 建连超时 |
| `acquire_timeout` | `10s` | 获取 Session 超时 |
| `query_timeout` | `30s` | 查询超时 |
| `batch_size` | `1000` | 单个 Tablet 最大行数 |
| `max_batch_bytes` | `4194304` | 单个 Tablet 估算字节上限 |
| `time_precision` | `ms`、`us`、`ns` | `time.Time` 的 IoTDB 精度 |

结构化配置的常用性能参数是 `BatchSize`、`MaxBatchBytes`、`PoolSize` 和 `TableInsertConcurrency`。应基于设备数、字段数和网络延迟压测后调整；不要通过无限增大批次或并发来替代容量评估。

## 6. 已支持与不支持的 GORM 用法

可使用：

- `Table`、`Select`、`Where`、`Order`、`Limit`、`Find`、`Scan`、`Raw`、`Exec`、`WithContext`；
- `Create`、`CreateInBatches`；
- TreeModel 和 TableModel 的非破坏性 `AutoMigrate`。

不支持且会返回明确错误：

- 默认事务、手工事务、SavePoint、RollbackTo；
- `Updates`、`Save`、GORM `Delete`；
- Association、Preload、Join、外键、唯一索引；
- 自动 Drop、Rename、类型修改；
- 将 TDengine 的 STABLE、子表、TAG 或 `last_row` 自动映射为通用 GORM 语义。

需要删除数据时，请按 IoTDB 模型显式执行经审查的 IoTDB SQL 或官方 API，不要调用 GORM `Delete`。

## 7. 验证与排查

本地单元测试不访问远端 IoTDB：

```bash
go test ./...
go test -race ./...
go vet ./...
```

真实环境测试通过环境变量开启。请使用独立的测试库/路径；测试会创建并删除唯一后缀的测试表或设备，但不会替你删除预先指定的 TableModel database：

```bash
IOTDB_TABLE_INTEGRATION=1 \
IOTDB_TABLE_NODE_URL=127.0.0.1:6667 \
IOTDB_TABLE_DATABASE=iotdb_gorm_test \
IOTDB_TABLE_USERNAME=root \
IOTDB_TABLE_PASSWORD='***' \
go test ./tests -run '^TestTableIntegration' -count=1 -v
```

发生连接或写入异常时，依次检查：服务端 `6667` 端口连通性、用户名和密码、模型与数据库名称是否匹配、账号的 DDL/写入权限、同一目标内是否出现重复时间戳，以及 `QueryTimeout` 是否覆盖实际查询耗时。
